요청을 전부 본다.무슨 뜻인지 묻는다.그대로 재현한다.

rever-browser는 진짜 크로미움 탭 옆에 리버싱 에이전트를 붙여 놓은 데스크톱 브라우저입니다. 사용자가 대상 사이트를 돌아다니면 앱이 CDP로 모든 요청을 기록하고, 에이전트가 그 트래픽을 읽고 자바스크립트 번들을 열어보고 탭을 직접 조작합니다.

데모 움직이는 화면은 영문 페이지에서 시나리오 7개를 눌러 볼 수 있습니다. 이 페이지는 문구만 옮긴 번역본입니다.

01 시나리오

열 마디 던지면, 동작하는 요청 하나가 나옵니다.

아래 항목은 전부 실제 앱을 그대로 녹화한 흐름입니다. 문장을 고르면 위쪽 화면이 그 장면을 재생합니다.

검색 API 찾아줘 로그인해서 내 주문 가져와 난독화 풀고 인증 흐름 찾아줘 웹소켓 해독해줘 limit=500으로 다시 보내줘 IDOR 있는지 확인해줘 이 과정 반복 가능하게 만들어줘

설명 예를 들어 “검색 API 찾아줘”라고 하면, 에이전트가 페이지를 스냅샷으로 뜨고 검색 버튼을 누른 뒤 잡힌 트래픽을 읽고 엔드포인트를 알려줍니다.

02 무엇이 들어 있나

브라우저와 패킷 캡처, 그리고 둘 다 읽는 에이전트.

따로 붙일 게 없습니다. 캡처 버퍼도, 번들 분석기도, 도구 서버도 지금 조작 중인 탭과 같은 창 안에 있습니다.

01

실시간 트래픽 캡처

탭에서 발생한 Network.* 이벤트가 전부 링 버퍼에 쌓입니다. 응답 본문은 loadingFinished 시점에 필요할 때만 가져오고, 이미지·비디오·폰트·CSS는 건너뛰어서 버퍼가 읽을 만한 상태로 유지됩니다.

cdpring bufferlazy bodieshar export
02

사용자가 보는 화면을 그대로 보는 에이전트

기본은 Claude Code, 대안으로 Codex를 쓸 수 있고 둘 다 stdio 위의 ACP로 붙습니다. 에이전트가 읽는 트래픽 저장소는 화면에 뜨는 것과 같은 저장소라, “방금 보낸 요청 설명해줘”에 복붙이 필요 없습니다.

acpclaude-agent-acpcodex-acpstreaming
03

브라우저 자동 조작

이동·클릭·입력·스크롤·스크린샷을 접근성 스냅샷 기반으로 실행합니다. 깨지기 쉬운 셀렉터 대신 짧은 rN 참조를 씁니다.

browser_snapshotbrowser_clickset_viewport
04

다시 내려받지 않는 번들 분석

이미 캡처에 들어 있는 자바스크립트를 그대로 grep 하고, 추출하고, 번들러를 판별하고, 난독화를 풉니다. webcrack이 PATH에 있으면 압축을 풀어 주고, 사이트가 소스맵을 제공하면 원본을 복원합니다.

grep_scriptsdetect_bundlerdeobfuscate_scriptsourcemap
05

깊게 파는 API 도구

리피터, 인트루더, 헤더 덮어쓰기, 요청 가로채기, 암호화·인코딩 해석 도우미, 웹소켓과 서비스 워커 점검, GraphQL·프로토버프 리더까지 들어 있습니다.

repeaterintruderinterceptgraphqlprotobuf
06

기본값이 로컬

MCP 서버는 앱 안에서 돌고 127.0.0.1의 임의 포트에 붙습니다. 에이전트를 처음 띄울 때만 시작되고, 캡처한 트래픽은 사용자 컴퓨터의 앱 메모리에 머뭅니다.

127.0.0.1in-process수집 서버 없음
07

알아낸 것을 반복 가능하게

엔드포인트를 파악했으면 매크로나 워크플로로 저장해 다시 실행하고, 세션 전체를 HAR로 내보내고, 앱 밖에서 돌릴 클라이언트 코드까지 받아볼 수 있습니다.

macrosworkflowsfindings
03 구조

프로세스 셋, 경계는 하나.

Node API와 CDP 디버거는 페이지 쪽으로 새어 나가지 않습니다. 모든 통신은 preload IPC를 거치고, 이 경계가 화면에 노출되는 API의 유일한 기준입니다.

main

크로미움과 에이전트를 소유

Node와 일렉트론 API를 쓸 수 있는 유일한 프로세스입니다.

  • webContents.debugger (CDP)
  • traffic-store 링 버퍼
  • ACP 자식 프로세스 실행
  • HTTP MCP 서버 구동
preload

둘 사이의 유일한 문

contextBridge로 window.rev만 노출합니다.

  • 타입이 정의된 RevAPI
  • 프롬프트별 업데이트 채널
  • 페이지로 Node가 넘어가지 않음
renderer

실제로 만지는 화면

React 19와 Vite로 만든 탭, 트래픽 목록, 채팅입니다.

  • <webview> 호스트
  • 실시간 트래픽 목록
  • 스트리밍 채팅 패널
캡처  ·  Network.* → traffic-store → network-event IPC → 트래픽 목록
에이전트  ·  프롬프트 → ACP 세션 → MCP 도구 → CDP → 스트리밍 답변
04 도구 목록

도구 134개, 알아내려는 것 기준으로 묶었습니다.

한 영역이 src/main/mcp/tools/ 아래 파일 하나입니다. 영역을 늘리려면 파일 하나 추가하고 서버 팩토리에 한 줄 넣으면 됩니다.

05 시작하기

1분이면 실행됩니다.

패키지 매니저는 npm이나 pnpm이 아니라 bun입니다. 에이전트 실행 파일은 별도 프로세스로 돌기 때문에 따로 설치합니다.

zsh
# 1 — PATH에 올라가야 하는 에이전트 실행 파일
$ npm i -g @agentclientprotocol/claude-agent-acp

# 2 — 앱
$ git clone https://github.com/greekr4/rever-browser
$ cd rever-browser
$ bun install
$ bun run dev

# 선택 — 캡처한 번들 난독화 풀기
$ npm i -g webcrack
01

대상 사이트를 연다

내장 탭 주소창에 URL을 넣습니다. 요청이 발생하는 대로 트래픽 목록에 쌓입니다.

02

채팅 패널을 연다

Claude Code나 Codex를 고릅니다. 세션은 API 리버싱용 시스템 프롬프트가 이미 걸린 상태로 시작합니다.

03

물어본다

“검색 엔드포인트는 뭘 받아?” 하면 에이전트가 캡처를 읽고 번들을 뒤진 뒤, 요청을 다시 보내 스스로 확인합니다.

04

남긴다

매크로로 저장하거나, HAR로 내보내거나, 생성된 클라이언트 코드를 앱 밖에서 실행합니다.

어디에 겨눌지 정하기 전에

rever-browser는 실제 브라우저로 실제 서버를 두드립니다. 본인이 운영하는 서비스, 서면으로 테스트 허가를 받은 시스템, 또는 테스트를 허용한 대상에만 쓰고, 해당 사이트의 약관과 거주 국가의 법을 따르세요.

이미 들여다볼 권한이 있는 사람을 위한 디버깅 도구입니다.

캡처를 읽고, 그다음 코드를 읽으세요.

MIT 라이선스이고 의존성 트리 어디에도 카피레프트가 없습니다. 이슈와 풀 리퀘스트 환영합니다.
